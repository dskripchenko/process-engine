# ADR-017. Отложенное из 1.0: кворум, откат сирот, сохранение таймеров, проверки здоровья

- Статус: принято автором 2026-11-01
- Дата: 2026-11-01

## Контекст

В 1.0 осознанно не вошли четыре вещи, названные в ADR как «позже»:
`join: {quorum: n}` (ADR-009 §1), `onOrphan: compensate` (ADR-006 §8),
`preserveTimers` при миграции (ADR-008 §3) и интеграция показателей здоровья
с laravel-admin-health (ADR-011). Автор решил сделать все четыре (мастер
вопросов 2026-11-01). Ниже — решения автора и детали, выбранные по умолчанию
(помечены «по умолчанию»; их можно поменять до кода).

Общий принцип: **обратная совместимость 1.x**. Поведение существующих
определений и живых экземпляров не меняется; новое включается явно. Релиз —
минорный (`process-engine` 1.3.0 и мосты).

## 1. Кворум: `join: {quorum: n}`

Решение автора:
- кворум есть и у `parallel`, и у `forEach`-детей (`invoke(Process, forEach:)`);
- `n` — число **или** метод процесса (как guards, через `$this->m(...)`),
  вычисляемый по контексту при входе в состояние;
- когда кворум набран, **оставшиеся ветки отменяются** — так же, как у
  `join: any` сейчас: регионы выходят с exit-действиями, их дети и эффекты
  становятся сиротами и идут по правилу `onOrphan` (§2).

```php
$b->parallel('approval', fn (Builder $p) => /* регионы */, join: quorum(2));
$b->invoke(Approve::class, forEach: 'approvers', join: quorum($this->m('majority')));
```

Детали (по умолчанию):
- `any` ≡ `quorum(1)`, `all` ≡ `quorum(m)`; в канонической форме —
  `{"quorum": n}` или `{"quorum": {"method": "majority"}}`; старые `all`/`any`
  читаются как раньше, хеш старых определений не меняется;
- вычисленное `n` фиксируется в снапшоте при входе (контекст позже его не
  меняет); `n < 1` или `n > m` — ошибка `error.execution` при входе;
- если кворум стал недостижим (ветки завершились ошибкой и оставшихся не
  хватает) — `error.quorum` с `{needed, done, failed}`;
- `done`-событие несёт выходы только завершившихся веток
  (`event.output.<regionId>` / список результатов детей в порядке
  завершения с индексом элемента);
- во flow-экспорте узел показывает `n/m` и прогресс (`2 из 3`).

## 2. Откат сирот: `onOrphan: compensate`

Сирота — эффект или дочерний процесс, чьё состояние-владелец экземпляр уже
покинул, а результат пришёл (или пришёл бы) позже. Сейчас результат только
пишется в журнал (`effect.orphaned`).

Решение автора: добавить `onOrphan: compensate`, по умолчанию — как сейчас
(`log`).

Детали (по умолчанию):
- где задаётся: у `invoke(...)` (точечно) и у процесса (`Builder::onOrphan()`,
  значение для всех вызовов), точечное важнее;
- эффект: работает только для `Compensable` (иначе ошибка валидации
  определения); когда результат сироты приходит, планируется его
  компенсация, запись журнала `effect.orphan_compensated`; неудача
  компенсации — инцидент `compensation_failed`, как у обычной компенсации;
- исход `unknown` у сироты at-most-once: сначала сверка (`Reconcilable`),
  компенсация — только если сверка показала, что эффект выполнен; инцидент
  `effect_unknown` поднимается, как и сейчас;
- дочерний процесс-сирота: отменяется (cancel) и проходит собственные
  компенсации в обратном порядке; его финал родителю не доставляется;
- на схеме откат сироты виден тоном `compensated` на узле-владельце.

## 3. Сохранение сроков таймеров при миграции: `preserveTimers`

Решение автора: опция миграции, по умолчанию выключена (таймеры
отсчитываются от момента миграции, как сейчас).

```php
$engine->migrate($migration->preserveTimers(), by: $actor, reason: '…');
```

Детали (по умолчанию):
- таймер старой версии сопоставляется с таймером новой по паре
  (новый id состояния по `stateMap`, событие таймера / индекс `after`);
  сопоставленный сохраняет исходный срок, несопоставленный создаётся заново;
- если сохранённый срок уже прошёл — таймер срабатывает на ближайшем tick
  (как просроченный), а не теряется;
- `at`-таймеры (абсолютная дата) сохраняют срок всегда — они от миграции не
  зависят (это исправление поведения: записать в CHANGELOG);
- dry run показывает по каждому таймеру: сохранён / создан заново / удалён.

## 4. Проверки здоровья в laravel-admin-health

Решение автора: все четыре проверки.

| Проверка (id) | Что смотрит | Порог по умолчанию |
|---|---|---|
| `process.incidents` | открытые инциденты | warning от 1, error от 10 |
| `process.unknown_effects` | эффекты в `unknown` старше порога | warning от 1 старше 15 мин, error старше 1 ч |
| `process.timers` | просроченные таймеры (`overdueAfter`) — признак, что tick не запущен | error от 1 |
| `process.queues` | необработанные inbox и неотправленный outbox старше порога — признак стоящих воркеров | warning старше 5 мин, error старше 15 мин |

Детали (по умолчанию):
- проверки живут в `laravel-admin-process` (не в ядре движка и не в
  laravel-admin-health); регистрируются, только если установлен
  `dskripchenko/laravel-admin-health` (`suggest`, не `require`);
- `Engine::health()` дополняется счётчиками `unknown_effects`,
  `stale_inbox`, `stale_outbox` (с порогом возраста) — без изменения
  существующих ключей;
- пороги — в конфиге `admin-process.health`; сообщение проверки содержит
  ссылку на список проблемных экземпляров в админке;
- частота — `1m` для таймеров и очередей, `5m` для инцидентов и `unknown`.

## Порядок и релизы

1. `process-engine` 1.3.0: кворум, `onOrphan`, `preserveTimers`, новые
   счётчики `health()`; тесты, включая харнесс падений для кворума и
   откатов сирот; flow-экспорт; доки en/ru/de/zh.
2. `laravel-process-engine` 1.x: счётчики inbox/outbox по возрасту в
   хранилище БД.
3. `laravel-admin-process`: четыре проверки здоровья, конфиг порогов.

Оценка: 1 — M/L (кворум и сироты затрагивают интерпретатор и исполнитель
эффектов), 2 — S, 3 — S.
