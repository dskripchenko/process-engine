# ADR-003. Стек и раскладка пакетов

- Статус: раскладка и имена согласованы автором 2026-10-26; правило зависимостей — решение автора
- Дата: 2026-10-26

## Контекст

Канон автора: PHP 8.2–8.5, Laravel 11/12/13, testbench ^9/^10/^11,
phpstan ^2 (level 5, baseline), pint (preset laravel), Pest. Есть прецедент
раскладки «чистое ядро + Laravel-мост»: `php-pdf` + `laravel-php-pdf`,
`php-docx` + `laravel-php-docx`.

Движку нужны: БД (снапшоты, inbox/outbox, таймеры, журнал), фоновые
исполнители, планировщик, DI. В Laravel это всё есть; но ядро
(интерпретатор, семантика эффектов) от фреймворка не зависит и должно
тестироваться без него.

## Решение

### Два пакета

| Пакет | Содержимое | Зависимости |
|---|---|---|
| `dskripchenko/process-engine` (этот репозиторий) | модель и DSL, валидатор, интерпретатор, рантайм (engine, runner, effect executor, sweeper), контракты хранилищ, in-memory хранилище, экспорт flow, тестовый харнесс (fault injection, виртуальные часы) | **только `php ^8.2`** |
| `dskripchenko/laravel-process-engine` (этап 7, отдельный каталог `~/www/forge/laravel-process-engine`) | миграции, хранилища на Query Builder (PostgreSQL, MySQL 8, SQLite), джобы очереди, команды `tick`/`sweep`/`work`/`doctor`/`archive`, провайдер, конфиг, события Laravel, мост к delayed-process | `dskripchenko/process-engine` + `laravel/framework ^11 \|\| ^12 \|\| ^13`; delayed-process — в `suggest` |

### Правило зависимостей (решение автора)

В `require` — только собственные пакеты автора и Laravel (для моста).
Никаких PSR-пакетов, symfony/*, ramsey/uuid, валидаторов JSON Schema и
т. п. Следствия:

- свои минимальные интерфейсы в ядре: `Clock` (`now(): DateTimeImmutable`),
  `Logger` (необязательный), `EventListener` для сигналов наблюдаемости,
  `Container` (`get(string $class): object`) для создания обработчиков;
  Laravel-слой реализует их поверх своих сервисов. Структурно они
  совместимы с PSR-20/PSR-3/PSR-14/PSR-11, но пакеты PSR не тянем;
- UUIDv7, ISO-8601-длительности и человекочитаемые интервалы (`'14 days'`),
  JSON Patch (RFC 6902) для журнала, сериализация контекста-DTO — свои,
  маленькие;
- YAML-определений нет (без symfony/yaml); формы — PHP DSL и JSON;
- в тестах схемы flow проверяются своим минимальным валидатором того
  подмножества JSON Schema, которое используют `graph.schema.json` и
  `snapshot.schema.json`.

Инструменты разработки (`require-dev`: Pest, phpstan, pint, testbench) —
по канону автора, в дистрибутив не попадают.

Неймспейсы: `Dskripchenko\ProcessEngine\…` и
`Dskripchenko\LaravelProcessEngine\…`.

Чистота ядра проверяется тестом архитектуры (Pest arch: `Dskripchenko\ProcessEngine`
не использует `Illuminate\*`, `Symfony\*`, кроме разрешённого списка).

### Почему ядро без Laravel

- Интерпретатор — чистая функция; его тесты (самые многочисленные) не должны
  поднимать приложение.
- Харнесс падений (ADR-013) детерминирован на in-memory хранилище с
  виртуальными часами — быстро и без гонок окружения.
- Ядро можно встроить в не-Laravel PHP (Symfony, консольный воркер),
  написав адаптер хранилища, — побочный выигрыш, не цель.

### Почему не одно-пакетный вариант

Один пакет с `require illuminate/*` проще в разработке, но противоречит
прецеденту автора и тянет фреймворк в ядро. Компромисс на время разработки:
мост лежит соседним каталогом и подключается path-репозиторием; публикация —
два репозитория (как php-pdf).

### Прочее

- PHP ^8.2: enum-ы, readonly-классы, first-class callable — всё доступно;
  фич 8.3+ (typed class constants, `#[\Override]`) в публичном API не
  используем.
- Идентификаторы экземпляров — UUIDv7 (сортируемые, как в delayed-process);
  генератор — свой в ядре.
- Сериализация — `json_encode` с `JSON_THROW_ON_ERROR | JSON_PRESERVE_ZERO_FRACTION`.
- Лицензия MIT, как у всех пакетов автора.

## Последствия

- Laravel-слой создаётся на этапе 7 в соседнем каталоге
  `~/www/forge/laravel-process-engine` (имена согласованы автором).
- До этапа 7 «настоящие» БД-гонки проверяются только в мосту; в ядре —
  детерминированной симуляцией (ADR-013).
