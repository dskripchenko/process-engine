# ADR-007. Формат определения: PHP DSL (класс процесса) + канонический JSON

- Статус: предложено; редакция 2 (2026-10-26) — по требованию автора минимизировать
  обвязку; клиентский код — [client-api.md](../client-api.md)
- Дата: 2026-10-26

## Контекст

Варианты: PHP DSL, декларативный JSON/YAML, оба. Факторы: удобство автора
процесса (IDE, рефакторинг, проверка типов), хранение версий в БД и
выполнение старых версий (ADR-008), экспорт во flow (ADR-012), в будущем —
визуальный редактор flow как источник определения. Требование автора:
**минимум обвязки** — этапы процессов сами по себе сложны, движок не должен
добавлять церемоний. Правило зависимостей (ADR-003): без symfony/yaml.

## Решение

### Две формы, одна каноническая

1. **Каноническая форма** — JSON-документ (массив PHP), описанный JSON
   Schema в пакете (`schema/definition.schema.json`). Он хранится в
   `pe_definitions`, хешируется, исполняется, экспортируется.
2. **PHP DSL** — класс процесса `extends Process` с методом
   `define(Builder $p)`; билдер **производит каноническую форму**.
   Основной способ писать процессы.
3. JSON-файл/массив — загрузка канонической формы напрямую (для будущего
   визуального редактора и генераторов). YAML не поддерживается.

Исполняется всегда каноническая форма. Старая версия исполняется **из БД**,
даже если граф в классе уже переписан под новую версию (ADR-008).

### Ссылки на поведение — методы и классы, без реестра

| Что | Как пишется в DSL | Как хранится |
|---|---|---|
| guard, изменение контекста (чистые) | `$this->isApproved(...)` — first-class callable метода класса процесса | `{"method": "isApproved"}` (класс процесса известен из определения) |
| эффект (побочное действие) | `RenderApplication::class` — invokable-класс | `{"effect": "App\\Processes\\Claim\\RenderApplication"}` |
| дочерний процесс | `DocumentRequest::class` (класс `extends Process`) | `{"process": "document-request"}` |
| встроенный предикат / assign | `eq('$.event.approved', true)` и т. п. | как есть |

- Различие «эффект / дочерний процесс» — по типу класса; «чистое действие /
  эффект» — по виду ссылки (метод процесса или класс). В `run:`, `entry()`,
  `exit()` можно смешивать.
- Анонимные замыкания запрещены (не сохраняются и не версионируются):
  билдер отличает ссылку на метод от анонимного замыкания через рефлексию и
  бросает понятную ошибку.
- Методы процесса вызываются через рефлексию (могут быть `private`),
  аргументы подставляются **по типу**: класс контекста или `array`, класс
  события или `array`, `StepContext` (время шага, id экземпляра, текущая
  конфигурация).
- Класс процесса создаётся **без аргументов конструктора**: в guards и
  чистых действиях нет DI — значит, нет ввода-вывода (ADR-002).
- Классы эффектов создаются контейнером (в Laravel — обычный DI), семантика
  повтора — атрибут на классе (ADR-006).
- **Регистрации нет**: определение регистрируется (с версией и hash) при
  первом `start()`; `process-engine:validate <paths>` — проверка в CI.

### Идентификаторы и умолчания

- id состояния **уникален в пределах процесса** — цели переходов пишутся
  коротко (`to: 'review'`), без путей и `#`. Полный путь
  (`review.awaitingDocuments`) вычисляется и используется в журнале и
  экспорте.
- id состояния — строка **или кейс backed enum** (`->state(ClaimState::Review, …)`,
  `to: ClaimState::Approved`). В каноническую форму пишется `value` кейса.
  Это даёт подсказки IDE и ловит опечатки в целях переходов ещё в редакторе.
  Enum на процесс — по желанию, строки остаются допустимыми, смешивать
  можно. Если enum задан константой `STATES` класса процесса, билдер
  дополнительно проверяет, что каждый кейс объявлен состоянием и каждое
  состояние есть в enum.
- Первое объявленное дочернее состояние — начальное (`->initial()` —
  переопределить).
- `on(Event, to:, from: [...] | '*')` на уровне процесса — переход из
  перечисленных состояний или из любого незавершённого (`'*'`). Сахар:
  разворачивается в переходы на каждом источнике (для `'*'` — на корне с
  guard «не в финале» не нужен: финалы событий не принимают).
- Имя события — строка или класс-DTO; имя класса-события по умолчанию — FQCN,
  `#[Event('party.decision')]` фиксирует стабильное внешнее имя (для
  вебхуков и переименований).
- Имя процесса — `#[ProcessName('claim-settlement')]` или kebab-case
  короткого имени класса; версия — константа `VERSION`.

### Контекст

`array` или класс с публичными свойствами (конструктор с promotion).
Свой сериализатор (ADR-003): скаляры, массивы, вложенные классы, enum,
`DateTimeImmutable`; списки объектов — атрибут `#[ListOf(X::class)]`.
Чистые действия мутируют объект контекста (или принимают `array &$context`);
движок сравнивает сериализованное «до/после» и пишет `context_patch`.
Эффекты контекст не меняют — возвращают результат (`into: 'prop'` или
`onDone` с методом).

### Встроенные декларативные guards

Для JSON-определений без PHP-класса — малый язык предикатов над
`context`/`event` (без eval):

```json
{"all": [{"eq": ["$.context.compensation", "repair"]},
         {"gt": ["$.event.amount", 0]},
         {"not": {"exists": "$.context.rejection"}}]}
```

Операторы: `eq ne gt gte lt lte in exists empty all any not` и `flag` —
значение именованного переключателя от хоста (`FlagProvider`), чтобы
включать/выключать ветку без новой версии; во flow это `enabled` ребра
(ADR-012). Пути — подмножество JSONPath (`$.context.a.b`, `$.event.x`).
В PHP DSL те же предикаты доступны функциями (`eq()`, `flag()`), но обычно
проще метод процесса.

### Валидация при сборке

Билдер проверяет при сборке: уникальность id, разрешимость целей,
достижимость, у составных есть дочерние, ссылки на методы существуют, классы
эффектов существуют и имеют атрибут семантики, у `choice` есть `otherwise`
(иначе предупреждение «может застрять»), сигнатуры методов совместимы с
местом использования (guard возвращает `bool`).

### Сахар билдера по итогам проверки на реальном процессе урегулирования (G2, G4, G5, G9)

Сахар разворачивается в обычные состояния и переходы канонической формы.
Граф остаётся явным, flow рисует его без знания о сахаре.

- **`steps('id', [step(X::class, into:, forEach:, id:), …], onDone:, onError:)`**
  (G2) — цепочка эффектов. Генерирует составное состояние `id`; на каждый
  шаг — атомарное состояние с `invoke` и переходом `done` → следующий шаг.
  id шага по умолчанию — `<id>_<lcfirst(КороткоеИмяКласса)>`, явный —
  `step(..., id: 'x')`. Ошибка шага после политики повторов уходит в
  `onError` цепочки, без него — инцидент.
- **`onDone: ['final' => 'target', …]` и `onError: ['code' => 'target', '*' => …]`**
  у `invoke` (G4) — маршрутизация по финалу дочернего процесса или по коду
  ошибки. Генерирует переходы с guard по `event.final` / `event.code`. Если
  класс ребёнка известен при сборке, билдер проверяет, что перечислены все
  его финалы.
- **`on(Event, match: 'field', targets: ['value' => 'target', …], otherwise:)`**
  и **`choice('id')->match('path', [...], otherwise:)`** (G5) — таблица
  маршрутов. Генерирует по переходу на значение с guard `eq`; строгое
  сравнение; путь — от события (`on`) или контекста (`choice`).
- **`meta(label:, description:)` у состояния и `label:` у перехода** (G9) —
  данные для UI. Ядро их не читает. `InstanceView::label()` возвращает
  метку самого глубокого активного состояния (для параллельных — список);
  `expects()` отдаёт события вместе с метками переходов — готовые кнопки
  для клиента (ADR-011).

## Последствия

- Методы процесса и классы эффектов, на которые ссылаются **живые версии**,
  нельзя удалять и несовместимо менять (ADR-008, `doctor`). Граф старой
  версии в коде держать не нужно — он в БД.
- Визуальный редактор flow в будущем может стать источником канонической
  формы — формат это допускает; на v1 не делаем.

## Отвергнутые альтернативы

- **Строковые имена обработчиков с реестром** (редакция 1). Лишняя
  регистрация, опечатки ловятся только при исполнении.
- **Атрибуты на методах как граф** (`#[On(...)]`). Граф размазывается,
  иерархию и регионы не выразить наглядно.
- **Только JSON.** Неудобно руками, нет помощи IDE.
- **symfony/expression-language для guards.** Запрещено правилом
  зависимостей и рискует «кодом в данных».
