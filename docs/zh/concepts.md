# 概念与保证

## 模型：带显式图的状态图（statechart）

流程定义是一个**状态图（statechart）**：包含可嵌套的状态（复合状态）、并行运行的
状态（并行区域）、终态、选择和历史状态。转换响应事件，可以带有守卫和动作，并在
状态之间移动。单步的语义遵循 W3C SCXML 算法：从最深的活动状态向上选择转换，解决
冲突的转换，按文档逆序退出状态、按文档顺序进入状态，无事件转换和内部事件持续执行，
直到不再发生变化。

图是**数据**。`Process` 类构建出规范的 JSON 形式；该形式会被计算哈希、按版本存储
并执行。由于图是显式的，引擎可以绘制它、告知某个实例当前接受哪些事件、按人工请求
将实例移动到任意状态，并让旧实例继续运行在其原有版本上。

## 单步是纯函数

```
step(definition, snapshot, event, time) → (snapshot', commands, journal data)
```

解释器没有存储、没有时钟，也没有副作用。副作用、定时器、轮询、订阅和子流程都以
**命令**的形式输出。随后运行时**在一个数据库事务中**写入：新的快照（按其版本号
校验）、日志条目、命令（outbox 行、定时器、订阅、子流程）以及事件的“已处理”标记。
要么全部保存，要么全部不保存。

流程类中的守卫和动作不获取任何服务，也不进行 I/O。它们只能看到上下文、事件和该步
的时间。所有与外部世界交互的操作都是副作用，在该步提交**之后**执行。

## 一切都经由收件箱（inbox）进入

外部事件、定时器触发、副作用结果、子流程完成和人工操作都是实例收件箱中的行，每行
都带有一个**幂等键**。重复的键会被报告为重复，不产生任何效果。同一实例的事件按到达
顺序逐个处理。

## 租约与隔离（fencing）

worker 在推进实例之前先获取该实例的一个短期**租约**，然后处理其收件箱。每一步只有在
快照的序列号仍是读取时的值时才会提交；租约已过期的 worker（长时间停顿、网络分区）
会发现实例已经前进，从而回滚。执行副作用期间不持有任何数据库锁，也不需要任何特定于
数据库的锁机制。

## 队列只是门铃

当一步产生了工作，运行时会在提交后“按响”调度器（在 Laravel 中是一个队列任务）。
丢失一次门铃不会丢失任何东西：周期性的 **tick** 会触发到期的定时器、恢复 worker
已崩溃的副作用，并为有待处理事件的实例重新按铃。长时间等待（数天、数周）是定时器行，
而不是延迟的队列任务。

## 保证

| 对象 | 保证 |
|---|---|
| 转换 | 每个收件箱事件恰好一次（去重 + 原子提交 + 隔离） |
| `#[Idempotent]` 副作用 | 至少一次；存疑时重试 |
| `#[AtMostOnce]` 副作用 | 每个键至多一次；存疑时变为 `unknown`，绝不自动重试 |
| 顺序 | 同一实例的事件按到达顺序；不同实例之间无顺序保证 |
| 时间 | 定时器在其时刻之后触发，精度取决于 tick（使用调度器时为一分钟，使用 worker 循环时为秒级） |

## 存储：快照加日志

**快照**（活动状态、上下文、激活计数器、历史）是执行的事实来源。**日志**是在同一
事务中写入的只追加历史：每一步都记录事件、所执行的转换、拒绝候选转换的守卫、上下文
补丁（RFC 6902）以及操作者。日志从不被重放以重建状态，但依次应用其上下文补丁可以
还原已存储的上下文，测试套件会对此进行校验。

已结束的实例会移入**归档**：每个实例一行压缩记录，包含其日志、副作用和事故
（incident），仍可通过同一 API 读取。

## 激活（activation）

每次进入一个状态都是一次新的**激活**（`review@3`）。副作用、定时器和订阅的键都带有
激活信息，因此再次进入同一状态的循环会重新开始，而较早激活的迟到结果会被丢弃，
不会推动实例。

## 事故（incident）

当某件事需要人来处理时——副作用重试次数耗尽、对账无法确定的未知结果、持续失败的
补偿、抛出异常的步骤——引擎会创建一个**事故（incident）**，流程的其余部分在可能的
范围内继续工作。事故通过人工操作关闭，人工操作会连同操作者和原因一起记入日志。
