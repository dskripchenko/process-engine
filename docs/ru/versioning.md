# Версии и миграции

## Версия никогда не меняется

Каждый класс процесса объявляет `VERSION`. При старте экземпляра
каноническая форма этой версии сохраняется вместе с хешем. Регистрация той
же версии с другим графом выбрасывает `DefinitionVersionConflict`: изменили
граф — поднимите версию.

```php
final class ClaimSettlement extends Process
{
    public const VERSION = 2;   // was 1
    // …
}
```

(При разработке можно разрешить переопределять версию, которую ещё не
использует ни один экземпляр: `new Engine(..., allowRedefineUnused: true)`.)

## Старые экземпляры завершаются на своей версии

Экземпляр привязан к сохранённой версии, с которой стартовал, и движок
исполняет **сохранённую форму**, а не класс. Можно переписать `define()` для
версии 2; экземпляры версии 1 продолжат работать на графе версии 1.

Новые экземпляры стартуют на версии, которую объявляет класс.
`start('claim-settlement')` по имени запускает последнюю сохранённую версию;
`start(..., version: 1)` — указанную.

Что должно оставаться в коде, пока у старых версий есть живые экземпляры:
**имена**, на которые они ссылаются, — методы класса процесса, используемые
как гарды и действия, классы эффектов, классы дочерних процессов. Несовместимо
меняйте поведение под новым именем (`ChargeV2`) и держите старое, пока его
экземпляры не исчезнут.

`$engine->doctor()` (artisan `process-engine:doctor`) перечисляет сохранённые
версии с живыми экземплярами, у которых пропали методы или классы.
Отсутствующий обработчик во время выполнения открывает инцидент, а не роняет
экземпляр.

## Миграция экземпляров

Миграция явная, поэкземплярная, пишется в журнал и сначала проверяется.

```php
use Dskripchenko\ProcessEngine\Versioning\Migration;

$migration = Migration::from(ClaimSettlement::class, 1)->to(2)
    ->mapState('waiting', 'awaitingParty')        // renamed states
    ->dropState('legacyFax')                      // instances standing here are not migrated
    ->context(fn (array $c) => [...$c, 'requests' => count($c['docRequests'] ?? [])])
    ->when(fn (InstanceView $i) => $i->businessKey() !== null);

$report = $engine->migrate($migration, Actor::operator('ann'), 'introduce the fraud check');   // dry run
$report->eligible;   // instance ids
$report->skipped;    // id => why not

$engine->migrate($migration, Actor::operator('ann'), 'introduce the fraud check', dryRun: false);
```

Экземпляр мигрирует, только когда он в покое:

- он работает на исходной версии и не завершён;
- нет открытых инцидентов;
- нет выполняющихся эффектов и эффектов с неизвестным исходом;
- нет работающих вызванных дочерних процессов;
- у каждого активного состояния есть пара в целевой версии (через карту или с
  тем же id).

Применение, под арендой экземпляра:

1. всё, что привязано к старым активациям, завершается: ожидающие эффекты,
   таймеры, опросы, подписки;
2. контекст преобразуется;
3. экземпляр входит в сопоставленные состояния новой версии **без действий
   входа** — это перемещение, а не новый вход; их таймеры, опросы, подписки и
   вызовы запускаются (таймеры отсчитываются от момента миграции);
4. в журнал попадает запись `migrated` с картой состояний, актором и причиной.

Миграции — это код, который запускает оператор, поэтому замыкания здесь
допустимы. Зарегистрируйте их через `$engine->registerMigration()`, чтобы
потом применять по имени
(`process-engine:migrate claim-settlement@1->2 --apply --reason=…`).

## Перенос процессов извне

`adopt()` создаёт экземпляр сразу в заданных состояниях — для процессов,
которые шли в унаследованном коде, или записей, созданных где-то ещё:

```php
$engine->adopt(ClaimCase::class, in: ['awaitingDocuments'], context: $context,
    key: "claim:{$legacyId}", by: Actor::operator('migration'), reason: 'move from the old system');
```

Действия входа не выполняются; таймеры, опросы, подписки и вызовы состояний
запускаются. Ключ делает пакетный импорт безопасным для повторного запуска.
