# Адаптеры хранилища

Движок сохраняет данные через один интерфейс,
`Dskripchenko\ProcessEngine\Store\Store`. Ядро поставляет `InMemoryStore`
(тесты, скрипты); мост для Laravel поставляет хранилище в базе данных для
PostgreSQL, MySQL / MariaDB и SQLite. Чтобы работать на чём-то другом,
напишите своё.

## Что требует контракт

- **`transaction(callable)`** — единица работы шага: всё, что записано внутри,
  фиксируется вместе или не фиксируется вовсе; вложенные вызовы
  присоединяются к внешней транзакции.
- **Fencing (защита по версии)** — `updateInstance($record, $expectedSeq)`
  пишет, только если сохранённый `seq` равен `$expectedSeq`, и иначе
  возвращает `false`. Именно это делает безвредным воркер с истёкшей арендой.
- **Compare-and-set** — `acquireLease()`, `claimEffect()` и `fireTimer()` —
  атомарные условные обновления (`UPDATE … WHERE status = ? …`), которые
  фиксируются сами по себе.
- **Идемпотентные вставки** — `insertInbox()` (уникальна по экземпляру и
  ключу), `insertEffect()` и `insertTimer()` (уникальный ключ),
  `insertMessage()` (уникальны событие + ключ корреляции + ключ),
  `insertInstance()` (уникальный id и бизнес-ключ в пределах процесса) при
  дубликате возвращают `false`, а не выбрасывают исключение.
- **Порядок** — `nextInbox()` возвращает ожидающие события в порядке
  поступления; `appendJournal()` назначает возрастающий `seq`.
- **Запросы** — экземпляры по статусу, процессу, версии, состоянию,
  бизнес-ключу, субъекту, инцидентам; наступившие таймеры и эффекты;
  истёкшие аренды; экземпляры, готовые к архивации.

Специфичные для СУБД блокировки не нужны: условных обновлений и уникальных
ключей хватает на любой SQL-базе.

## Таблицы (хранилище в базе данных)

| Таблица | Хранит |
|---|---|
| `definitions` | сохранённые версии: имя, версия, хеш, канонический JSON |
| `instances` | снапшот, seq, аренда, родитель, бизнес-ключ, субъект |
| `active_states` | активные состояния строками, для индексированного запроса «экземпляры в состоянии X» |
| `inbox` | события с ключами и статусом |
| `effects` | outbox: ключ, класс, семантика, политика, статус, попытка, аренда, результат |
| `timers` | ключ, событие, момент, статус |
| `subscriptions`, `messages` | корреляция и буфер ранних событий |
| `incidents`, `journal` | |
| `archive` | один сжатый документ на завершённый экземпляр |

## Масштаб

Дизайн рассчитан примерно на 100 000 активных экземпляров и 10 миллионов
архивных: горячие таблицы хранят только активные и недавно завершённые
экземпляры, а архивный экземпляр — это одна строка. Журналы активных
экземпляров читаются постранично по `(instance_id, seq)`.

## Замечания для SQLite

При нескольких воркерах настройте соединение с
`transaction_mode = IMMEDIATE` и WAL: отложенные транзакции, которые
повышаются до записи, падают с «database is locked» вместо ожидания. Для
одного воркера или тестов подойдут настройки по умолчанию.
