# Структура: вложенность, параллельные регионы, история, дочерние процессы

Есть два вида структуры с разной ценой: внутри одного экземпляра (составные
и параллельные состояния) и между экземплярами (дочерние процессы).

## Составные состояния

```php
$p->state('application', fn (Builder $s) => $s
    ->after('14 days', to: 'abandoned')              // applies to every state inside
    ->on('client.cancelled', to: 'cancelled')        // so does this
    ->state('filling', fn (Builder $s) => $s->on(FormSubmitted::class, to: 'signing'))
    ->state('signing', fn (Builder $s) => $s->on('client.signed', to: 'signed'))
    ->final('signed')
    ->onDone(to: 'review'));
```

- Дочерние состояния делят контекст и журнал.
- Переходы, объявленные на составном состоянии, работают из любого состояния
  внутри него: таймер на `application` — это срок для всего этапа.
- Достижение финального дочернего состояния порождает `done.state.<id>`;
  `onDone()` реагирует на него.

## Параллельные состояния

```php
$p->parallel('agreement', fn (Builder $s) => $s
    ->region('compensation', fn (Builder $r) => $r
        ->state('offering', fn (Builder $s) => $s->on('client.accepted', to: 'agreed'))
        ->final('agreed', output: 'compensation'))
    ->region('service', fn (Builder $r) => $r
        ->state('choosingSlot', fn (Builder $s) => $s->on('client.slot-chosen', to: 'booked'))
        ->final('booked'))
    ->onDone(to: 'route'), join: 'all');
```

- `join: 'all'` (по умолчанию): готово, когда каждый регион достиг своего
  финального состояния; событие `done` несёт output каждого региона.
- `join: 'any'`: готово, когда завершился первый регион; из остальных
  регионов выполняется выход, их ожидающие эффекты и дочерние процессы
  отменяются.
- Регионы логически параллельны и физически последовательны (одна аренда на
  экземпляр); их эффекты выполняются по-настоящему параллельно.

## История

```php
$p->state('work', fn (Builder $s) => $s
    ->on('pause', to: 'paused')
    ->state('step1', /* … */)
    ->state('step2', /* … */)
    ->history('resume')                 // shallow: the last active child
    ->history('resumeDeep', deep: true)); // deep: the exact nested states
$p->state('paused', fn (Builder $s) => $s->on('continue', to: 'resume'));
```

Вход в состояние истории восстанавливает конфигурацию, которая была у
родителя при последнем выходе из него (в первый раз — начальное состояние
родителя или `default:`).

## Дочерние процессы

Состояние может запустить другой процесс как отдельный экземпляр:

```php
->invoke(DocumentRequest::class,
    input: $this->requestInput(...),
    onDone: ['signed' => 'review', 'refused' => 'refused', 'expired' => 'refused'],
    onError: 'failed')
```

- У дочернего процесса своя версия (фиксируется при старте), контекст, журнал
  и аренда. Он видит только свой `input`; родитель видит только его `output`
  (`final('signed', output: 'files')`).
- `onDone` с картой маршрутизирует по финальному состоянию дочернего
  процесса; билдер проверяет, что каждое его финальное состояние направлено.
- Если родитель покидает состояние, дочерний процесс отменяется. Упавший или
  отменённый дочерний процесс отправляет `error.invoke.<id>` с кодом
  `child_failed` / `child_cancelled`.

### Один дочерний процесс на элемент

```php
->invoke(SignDocument::class, forEach: 'documents', into: 'signatures', onDone: 'done')
```

N дочерних процессов, результаты собираются в порядке списка, готово, когда
завершились все.

### Один дочерний процесс на событие: `spawn`

```php
$p->on(NotificationReceived::class, spawn: ClaimRequest::class, input: $this->requestInput(...), key: 'messageId');
```

- Дочерний процесс стартует на каждое событие, без перехода у родителя.
- `key` (поле события) отсекает дубликаты: одно и то же значение никогда не
  запустит второй дочерний процесс.
- Дочерний процесс живёт, пока жива область, где объявлен `spawn` (состояние
  или весь процесс); `onScopeExit: 'keep'` позволяет ему пережить эту область.
- Его завершение приходит как `done.spawn.<id>`; реагировать необязательно.
  `StepContext::spawned()` считает живые дочерние процессы для гардов.

## Что выбрать

| Задача | Решение |
|---|---|
| этапы одного процесса, общий контекст, «из любого места этапа» | составное состояние |
| ветви, идущие одновременно и затем сходящиеся | параллельное состояние |
| переиспользуемый фрагмент со своей версией и жизненным циклом | дочерний процесс |
| N похожих ветвей по данным | `invoke(..., forEach:)` дочернего процесса |
| N похожих внешних вызовов по данным | `invoke(..., forEach:)` эффекта |
| подпроцессы, приходящие событиями, число которых заранее неизвестно | `spawn` |
